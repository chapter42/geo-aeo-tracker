<task type="auto">
  <name>Task 1: Create proxy.ts request interceptor</name>
  <files>proxy.ts</files>
  <action>
Create `proxy.ts` at the project root (same level as `app/`, `lib/`, `package.json`).

This file uses the Next.js 16 proxy convention (NOT middleware.ts which is deprecated).

Export an async function named `proxy` and a `config` object:

```
proxy function logic:
  1. Extract pathname from request.nextUrl
  2. Early return NextResponse.next() for public paths:
     - pathname === '/login'
     - pathname === '/api/auth/login'
     (These must be accessible without auth — otherwise login is impossible)
  3. Read session cookie: request.cookies.get('session')?.value
  4. Call decrypt(sessionCookie) from '@/lib/auth'
  5. If session is null (invalid/missing/expired):
     a. If pathname.startsWith('/api/'):
        Return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
     b. Else (page request):
        Build login URL: new URL('/login', request.url)
        Set callbackUrl param: loginUrl.searchParams.set('callbackUrl', pathname)
        Return NextResponse.redirect(loginUrl)
  6. If session is valid: return NextResponse.next()
```

Config matcher — use negative lookahead regex to exclude static assets:
```typescript
export const config = {
  matcher: [
    '/((?!_next/static|_next/image|favicon\\.ico).*)',
  ],
}
```

This matcher excludes _next/static, _next/image, and favicon.ico (AUTH-06). All other routes INCLUDING /api/* are matched (AUTH-05 — proxy-level defense-in-depth for API routes without modifying upstream files).

IMPORTANT implementation details:
- Import decrypt from '@/lib/auth' — do NOT import cookies() from next/headers. In proxy.ts, use request.cookies.get() (Pitfall from research: cookies() is not available in proxy context).
- The function export MUST be named `proxy` (not `middleware` — Next.js 16 convention).
- Do NOT add `server-only` import.
- Do NOT exclude `_next/data` from the matcher (Pitfall 2 from research — security hole).
- Do NOT exclude `/api` from the matcher (Pitfall 1 from research — leaves API routes unprotected).

<task type="auto">
  <name>Task 2: Create login page at app/login/page.tsx</name>
  <files>app/login/page.tsx</files>
  <action>
Create directory `app/login/` if it does not exist.

Create `app/login/page.tsx` as a client component (`'use client'` directive) with a login form.

The page must:

1. Read `callbackUrl` from URL search params using `useSearchParams()` from `next/navigation`. Default to `'/'` if not present.

2. Render a simple form with:
   - A password input field (type="password", required)
   - A submit button ("Log in" or "Enter")
   - An error message area (initially hidden)

3. On form submit (prevent default):
   - Set loading state
   - POST to `/api/auth/login` with `{ password }` as JSON body
   - Content-Type: 'application/json'
   - On success (response.ok): call `router.push(callbackUrl)` using `useRouter()` from `next/navigation`
     - Use client-side redirect, NOT server 302 (Pitfall 6 from research: cookie race condition — browser needs time to commit Set-Cookie before navigating)
   - On failure: parse response JSON, display `error` field as inline error message (e.g., "Incorrect password")
   - Clear loading state

4. Minimal styling for Phase 1 (Phase 2 handles visual polish):
   - Center the form on the page
   - Basic Tailwind classes: `flex items-center justify-center min-h-screen`
   - Form container with some padding: `p-8 rounded-lg max-w-sm w-full`
   - Use the existing dark theme background (inherited from layout.tsx)
   - Error text in red: `text-red-500`
   - Basic input styling: border, padding, full width
   - Button with basic styling

5. Wrap `useSearchParams()` usage in a Suspense boundary. Since the entire file is `'use client'`, use this pattern:
   - The file starts with `'use client'`
   - Create a `LoginForm` component that uses `useSearchParams()` and `useRouter()`
   - Export default a wrapper that renders `<Suspense><LoginForm /></Suspense>`
   - Both components are in the same client file

Do NOT import anything from lib/auth.ts in this file — the login page is a client component and auth utilities are server-only. All auth interaction goes through the `/api/auth/login` fetch call.
