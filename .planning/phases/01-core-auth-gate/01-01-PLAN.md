<task type="auto">
  <name>Task 1: Install jose and create lib/auth.ts session utilities</name>
  <files>lib/auth.ts, package.json</files>
  <action>
1. Run `npm install jose` to add the jose library (v6.x).

2. Create `lib/auth.ts` with the following exports:

- `encrypt(payload: Record<string, unknown>): Promise<string>` — Creates a signed JWT using jose `SignJWT` with HS256 algorithm, sets `iat` and 7-day expiration. Signs with `AUTH_SECRET` env var encoded via `TextEncoder`.

- `decrypt(session: string | undefined): Promise<JWTPayload | null>` — Verifies JWT using jose `jwtVerify` with HS256. Returns payload on success, `null` on any error (expired, invalid, undefined input). Wrap in try/catch.

- `createSession(): Promise<void>` — Creates a 7-day JWT via `encrypt({ authenticated: true, expiresAt })`, then sets cookie named `session` via `cookies()` from `next/headers`. Cookie options: `httpOnly: true`, `secure: process.env.NODE_ENV === 'production'`, `expires: expiresAt` (Date object, 7 days from now), `sameSite: 'lax'`, `path: '/'`.

- `verifySession(): Promise<JWTPayload | null>` — Reads `session` cookie via `cookies()` from `next/headers`, passes value to `decrypt()`, returns result.

Key implementation details:
- Read `AUTH_SECRET` from `process.env.AUTH_SECRET` at module level. Add a guard: `if (!secretKey) throw new Error('AUTH_SECRET environment variable is required')` — but only when the functions are called, not at import time (proxy.ts will import this file and the env var must be available at runtime, not build time). Use a lazy getter pattern: `const getEncodedKey = () => new TextEncoder().encode(process.env.AUTH_SECRET!)` and validate inside encrypt/decrypt.
- Do NOT add `import 'server-only'` — proxy.ts imports this file and proxy is not a React server context. The `server-only` marker will crash.
- Do NOT use `cookies()` in any function that proxy.ts calls. Only `createSession()` and `verifySession()` use `cookies()`. The `encrypt()` and `decrypt()` functions must NOT import or call `cookies()` — they are pure JWT operations.
- Use `expires` (not `maxAge`) for the cookie — per locked decision.
- Import order: jose imports first, then next/headers, then nothing else.

<task type="auto">
  <name>Task 2: Create login API route at app/api/auth/login/route.ts</name>
  <files>app/api/auth/login/route.ts</files>
  <action>
1. Create directory `app/api/auth/login/` if it does not exist.

2. Create `app/api/auth/login/route.ts` with a single `POST` export:

```
POST handler:
  1. Parse request body as JSON
  2. Validate with Zod schema: z.object({ password: z.string().min(1) })
  3. Read SITE_PASSWORD from process.env — if missing, return 500 { error: 'Server misconfigured' }
  4. Compare password using crypto.timingSafeEqual():
     - Convert both to Buffers via Buffer.from()
     - Check lengths first: if inputBuf.length !== expectedBuf.length, set match = false
     - Only call timingSafeEqual if lengths match
     - This prevents the throw on unequal lengths (Pitfall 7 from research)
  5. If no match: return 401 { error: 'Incorrect password' }
  6. If match: call createSession() from @/lib/auth, then return 200 { success: true }
```

Follow existing API route patterns in this codebase:
- Import NextRequest, NextResponse from 'next/server'
- Import z from 'zod'
- Import createSession from '@/lib/auth'
- Import crypto from 'crypto' (Node.js built-in, NOT jose)
- Define Zod schema as const at module level (e.g., `const LoginSchema = z.object(...)`)
- Use try/catch with `error instanceof Error ? error.message : 'Unknown error'` fallback
- Return JSON responses via NextResponse.json()

Do NOT use edge runtime — this route needs Node.js crypto.timingSafeEqual() which requires the Node.js runtime.
