# Plan 05-01: API Defense-in-Depth & Prompt Cap Fix

## Goal

Add independent `verifySession()` guards to the three API route handlers (`/api/scrape`, `/api/audit`, `/api/analyze`) so they reject unauthenticated requests with a 401 JSON response regardless of proxy state. Simultaneously remove the 50-prompt cap from `addCustomPrompt()` in `sovereign-dashboard.tsx` so bulk import is not silently truncated.

## Context

- `verifySession()` is fully implemented in `lib/auth.ts` (uses `cookies()` from `next/headers` + `jose` JWT verify). No new packages needed.
- The three route handlers currently have zero auth checks — the proxy is their only guard. This fails the defense-in-depth requirement (AUTH-05) and is a CVE-2025-29927 class vulnerability.
- `/api/analyze/route.ts` declares `export const runtime = "edge"`. This is safe: `verifySession()` uses only `cookies()` (next/headers, edge-compatible since Next.js 13.4) and `jose` (Web Crypto API based, explicitly edge-compatible). The `runtime = "edge"` line must be preserved.
- The sole prompt cap is `.slice(0, 50)` at line 901 in `addCustomPrompt()` inside `sovereign-dashboard.tsx`. A second `.slice(0, 50)` exists at line 546 (citation URL sorting inside a `useMemo`) — that one must NOT be touched.
- API routes must return JSON `{ error: 'Unauthorized' }` with status 401, NOT a redirect. This is an established project decision (STATE.md `[01-02]`).
- Do NOT add `server-only` to `lib/auth.ts` — proxy.ts imports it and `server-only` would crash in proxy context (STATE.md `[01-01]`).
